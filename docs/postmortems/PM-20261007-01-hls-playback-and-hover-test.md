# PM-20261007-01: HLS 재생 판정과 검색 직후 호버 검증 실패

## 1. 요약

공식 영상의 HLS 재생을 추가하면서 브라우저의 지원 응답을 실제 재생 가능성으로 잘못 해석했습니다.
재생 경로를 수정한 다음에는 검색 화면 갱신 전에 이전 카드를 가리키는 테스트가 별도로 실패했습니다.
두 원인을 구분해 수정하고 상세 영상과 호버 미리보기의 실제 시간 증가를 확인했습니다.

## 2. 증상

첫 `scripts/test-stream.cjs` 실행은 상세 영상의 재생 시간 증가를 기다리다가 시간 초과로 끝났습니다. Chrome의 `canPlayType`은 HLS에 `maybe`를 반환했지만 선택한 기본 재생 경로에서는 재생되지 않았습니다.

독립 실험에서는 hls.js의 지원 여부가 true였고 재생 시간이 4.927초까지 증가했습니다. 해당 경로로 수정한 다음 실행은 상세 재생을 통과했지만 호버 검사에서 실패했습니다. 두 번째 실패는 영상 재생 엔진 오류가 아니라 검색 직후 이전 카드에 마우스를 올린 테스트 순서 문제였습니다.

## 3. 타임라인

정확한 시도별 시작 시각은 보존되지 않았습니다. 아래 12:23은 최종 `qa/stream-run.log` 수정 시각에서 가져온 대략적인 세션 기준점이며, 각 실패가 그 분에 발생했다는 뜻은 아닙니다. 순서는 실제 관찰 순서입니다.

- 12:23 가설: 기본 브라우저 지원 응답이면 HLS를 재생할 수 있습니다. → 시도: 상세 영상의 재생 시간 증가를 기다렸습니다. → 결과: FAIL — 시간 초과가 발생했습니다. 시각은 위 기준점으로만 표시합니다.
- 12:23 가설: hls.js를 우선 사용하면 실제 재생이 됩니다. → 시도: 지원 여부와 독립 재생을 확인하고 실행 경로를 바꿨습니다. → 결과: PASS — 독립 실험에서 4.927초까지 증가했습니다. 시각은 위 기준점으로만 표시합니다.
- 12:23 가설: 검색어 입력 직후 첫 카드가 목표 작품입니다. → 시도: 즉시 첫 카드에 마우스를 올렸습니다. → 결과: FAIL — 이전 검색 상태의 카드를 가리켰습니다. 시각은 위 기준점으로만 표시합니다.
- 12:23 가설: 검색 갱신과 정확한 작품 경로를 확인해야 합니다. → 시도: 400ms 대기와 정확한 slug 경로 선택을 적용했습니다. → 결과: PASS — 상세 0.530193초, 호버 0.51408초의 실제 재생을 확인했습니다. 시각은 로그 수정 시각 기준입니다.

## 4. 근본 원인

첫 실패는 기능 지원 힌트와 실제 네트워크·디코딩·재생 결과를 같은 것으로 취급한 데서 시작했습니다. 그 결과 hls.js가 지원되는 환경에서도 기본 브라우저 경로가 먼저 선택됐고, 재생 검증에서야 문제가 드러났습니다.

두 번째 실패는 검색 입력과 화면 갱신을 하나의 즉시 작업으로 취급한 데서 시작했습니다. 위치 기반 첫 카드 선택이 이전 렌더 상태에도 유효했으므로, 테스트는 사용자가 의도한 새 검색 결과가 아닌 카드를 검사했습니다. 재생 실패와 테스트 대상 선택 실패는 서로 다른 원인입니다.

## 5. 관점 분석

- 기술: `canPlayType`의 가능성 응답은 실제 재생을 보장하지 않았습니다. HLS 지원 경로 선택과 재생 시간 증가를 각각 확인해야 했습니다.
- 프로세스: 검색 갱신 이후 목표 경로를 선택하는 조건이 없어서 정상 재생 수정 후에도 테스트가 잘못 실패했습니다.
- AI협업: 구현자가 브라우저 지원 응답을 충분한 증거로 해석했고, 테스트에서는 입력 직후 화면 갱신을 가정했습니다. 독립 재생 실험과 정확한 대상 지정이 두 가정을 분리했습니다.

## 6. 해결

`lib/use-stream.ts`에서 `Hls.isSupported()`를 먼저 확인하고 hls.js 경로를 사용하도록 변경했습니다. 해당 경로를 사용할 수 없을 때 기본 재생 경로를 선택합니다. 호버 테스트는 검색 이후 400ms 대기와 정확한 작품 slug 경로를 함께 사용합니다.

현재 파일에서 직접 읽은 실측 로그는 다음과 같습니다. 과거 두 실패의 원본 전체 로그는 별도로 보존되지 않았으며, 해당 경위는 실행 담당자의 보고를 바탕으로 구분해 기록했습니다.

```text
$ cat qa/stream-run.log
PASS streaming detail and hover remotion-travel-route-on-map-with-3d-landmarks { time: 0.530193, muted: true, readyState: 4 } { time: 0.51408, muted: true }
```

## 7. 재발 방지

`lib/use-stream.ts`는 HLS 지원 경로를 명시적으로 선택합니다. `scripts/test-stream.cjs`는 상세 재생과 검색 후 호버 재생의 실제 시간 증가를 확인하며, 결과는 `qa/stream.json`과 `qa/stream-run.log`에 남깁니다. 영상 지원 선언만으로 완료를 판정하지 않습니다.

## 8. 다음 세션 룰 후보

영상은 지원 힌트가 아니라 재생 시간 증가로 확인하고, 비동기 검색 뒤에는 위치 대신 정확한 작품 경로를 선택합니다.
